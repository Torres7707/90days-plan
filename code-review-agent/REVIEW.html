2 核心功能需求

FR-1 代码输入与提交

描述：用户粘贴React/TypeScript代码到编辑器

输入：React组件代码文本

输出：提交审核请求

约束条件：

  • 支持 GitHub URL 输入（推荐）
  • 支持手动粘贴代码（备选）
  • 空输入时禁用提交按钮
  • 显示当前状态（空闲/流式处理中）

FR-2 AI代码审查

描述：使用LLM分析代码，识别真实问题

审查规则：

  • 仅报告真实问题（bug、hook误用、依赖数组缺失、闭包过期、缺少key等）
  • 按严重程度排序：🔴 High → 🟡 Medium → 🟢 Low
  • 每条问题包含：代码片段、原因说明（Why）、修复建议（Fix）
  • 无问题时回复："No problems found ✅"
  • 响应语言与用户输入语言一致

FR-3 流式输出展示

描述：实时展示AI审查结果，带有动画效果

技术特性：

  • 使用AI SDK v7的流式响应
  • 逐字流式渲染
  • 支持Markdown格式展示
  • 显示token使用统计

FR-4 交互控制

描述：用户可中断流式响应

功能：

  • Stop按钮：中断当前流式生成
  • Review按钮：触发代码审查
  • 状态指示：显示当前是否在处理中

  3. 可扩展性强：未来可加入行号、文件树、diff视图等功能

GitHub URL方案

🎯 核心问题

痛点：当前交互需要手动复制、粘贴代码，这在真实开发工作流中极其不自然。 开发者不是Copy/Paste的机器——他们的代码在Git仓库里、在PR里、在本地IDE中。

✅ 推荐解决方案

  1. GitHub URL 输入：支持 GitHub Repo / File / PR 链接
  2. 智能代码拉取：后端调用 GitHub REST API 获取代码内容
  3. 自动 Diff 审查：PR链接自动提取变更内容进行审查
  4. 保留手动粘贴：作为备选方案，支持小段代码快速审查

1️⃣ 输入检测

// 判断输入类型
function detectInputType(input: string): 'github-url' | 'raw-code' {
  const githubUrlPattern = /^https?:\/\/github\.com\/...;
  return githubUrlPattern.test(input) ? 'github-url' : 'raw-code';
}

2️⃣ GitHub API 调用

// 服务端：拉取文件内容
async fetchGitHubFile(url: string): Promise<string> {
  const apiUrl = url.replace('github.com', 'api.github.com/repos');
  const res = await fetch(apiUrl, {
    headers: { Accept: 'application/vnd.github.raw' }
  });
  return res.text();
}

// 拉取 PR diff
async fetchPRDiff(repo: string, prNumber: number): Promise<string> {
  const res = await fetch(
    `https://api.github.com/repos/${repo}/pulls/${prNumber}`,
    { headers: { Accept: 'application/vnd.github.v3.diff' } }
  );
  return res.text();
}

📈 实际场景

  • Code Review 时复制 PR 链接
  • 审查开源项目特定文件
  • 快速检查依赖库的使用是否正确
  • 教学演示时指向示例仓库

⚠️ 注意事项

  • GitHub API 限额：未认证 60次/小时；需要 Option Pro/Team 或配置 GITHUB_TOKEN
  • 私有仓库：需要用户授权 token，当前版本暂不支持（后续迭代）
  • 大文件限制：GitHub API 限制 1MB，PR diff 通常不会超过
  • 网络延迟：首次拉取可能 1-2秒，可在 UI 显示加载状态
  • 错误处理：404（不存在）、403（无权限）、422（无效URL）需要友好提示
