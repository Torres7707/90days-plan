# 从 LLM 到 Agent Skill（马克的技术工作坊）

视频：https://www.youtube.com/watch?v=7qO8-kx3gW8
整理日期：2026-10-31（根据视频字幕整理，下面是视频里的说法）

## 概念一层层往上搭

- **LLM**：本质是文字接龙，一次预测一个 token。
- **Tokenizer**：负责文字和数字互转（编码：切分 + 映射成 Token ID；解码：映射回文字）。token 不等于词，平均一个 token 约 0.75 个英文单词，或 1.5 到 2 个汉字。
- **Context（上下文）**：模型每次处理任务收到的全部信息，包括用户问题、对话历史、工具列表、System Prompt 等。模型本身没有记忆，每次都是把历史重新发一遍。
- **Context Window**：Context 最多能装多少 token。
- **Prompt**：User Prompt 是用户输入的；System Prompt 是开发者在后台设的人设和规则。
- **Tool（工具）**：本质是函数。模型自己不能调用工具，只能输出一条"想调用哪个工具、参数是什么"的文本，由平台真正执行，再把结果交回模型总结。
  - 模型：选工具、总结结果。
  - 工具：干活。
  - 平台：传话，串联整个流程。
- **MCP**：统一的工具接入标准。工具写一次，所有支持 MCP 的平台都能用（类似 Type-C）。
- **Agent**：能自己规划、连续调用多个工具直到完成任务的系统（例子：先定位，再查天气，再找雨伞店）。经典构建模式有 ReAct、Plan-and-Execute。
- **Agent Skill**：给 Agent 看的 Markdown 说明书。
  - 元数据层：`name`、`description`。
  - 指令层：步骤、规则、输出格式、示例。
  - 文件夹名要和 skill 名一致，文件必须叫 `SKILL.md`。
  - 启动时只读元数据，问题相关时才读指令层，这叫渐进式披露，能省 token。

## 我自己的理解（看完后用自己的话补）

用新能源汽车来类比，大致是这样：

- **LLM**：相当于电机。它只做一件事，就是一次往前"转"一小步（预测下一个 token），本身不认路，也不会自己开去哪儿。
- **Token**：相当于电量的最小计量单位。你输入多少、模型输出多少，都按 token 算，电费（调用费用）也按它计。
- **Tokenizer**：相当于充电枪的转换接口，把你的话切成电机能用的"标准电流"，输出时再转换回来。
- **Context**：相当于仪表盘上这一趟行程的全部信息：目的地、路况、之前走过的路线、车上能用的功能。电机没有记忆，每次踩油门都要把这些重新读一遍。
- **Context Window**：相当于电池容量。装得下的行程信息有上限，满了就得删旧的。
- **Prompt**：User Prompt 是乘客说的话，比如"去机场"。System Prompt 是出厂设定，比如限速、驾驶风格、安全规则。
- **Tool**：相当于车上的各个部件，比如空调、导航、雨刷。电机自己不会按空调开关，它只能"发出请求"，由车机系统去真正执行，再把结果反馈回来。
- **MCP**：相当于统一的充电接口标准。部件和充电桩按同一个标准做，哪个品牌的车都能插上用。
- **Agent**：相当于带自动驾驶的整车。你只说"去机场"，它自己规划路线、避开拥堵、中途找充电站，一路调用各个部件，直到到达。ReAct 像是边走边看路况再决定，Plan-and-Execute 像是先规划完整路线再出发。
- **Agent Skill**：相当于车载的驾驶手册。启动时只看目录（name 和 description），遇到具体情况，比如"雪天怎么开"，才翻到对应那一章。这就是渐进式披露，不用每次把整本手册都塞进仪表盘，能省电量（token）。

有一点这个比喻不完全准：电机是物理装置，而 LLM 每次回答都是"重新读完整个行程再推理一遍"，所以更像一台每次启动都失忆、全靠仪表盘上的信息才知道自己在干嘛的电机。
