# Agent Skill 是什么，怎么用，和 MCP 的区别（马克的技术工作坊）

视频：https://www.youtube.com/watch?v=yDc0_8emz7M
整理日期：2026-11-01（根据视频字幕整理，下面是视频里的说法；时长约 17 分钟）

## 背景

- 2025-10-16：Anthropic 推出 Agent Skill，起初定位克制，只是提升 Claude 在特定任务上的表现。
- 后来 VS Code、Codex、Cursor 等工具陆续支持。
- 2025-12-18：Anthropic 把它发布为**开放标准**，可跨平台、跨产品复用，正在变成 AI Agent 领域的通用设计模式。

## 一句话理解

Agent Skill 就是**大模型可以随时翻阅的说明文档**。
- 例：智能客服 Skill 写明"遇到投诉先安抚情绪，不得随意承诺"。
- 例：会议总结 Skill 规定"必须按参会人员、议题、决定的格式输出"。
- 好处：不用每次对话都重复粘贴一长串要求。
- 视频说明："说明文档"只是方便理解的简化说法，Skill 实际能力更强（见后面 Reference 和 Script）。

## 基本用法（视频里的演示）

1. 在用户目录的 `.claude` 下的 skill 文件夹里建一个文件夹，**文件夹名就是 Skill 的名字**。
2. 文件夹里建 `SKILL.md`，分两部分：

| 部分 | 内容 |
| --- | --- |
| 头部（两行 `---` 之间）：元数据 Metadata | 只写 `name`（必须和文件夹同名）和 `description`（告诉模型这个 Skill 干什么用） |
| 正文：指令 Instruction | 模型要遵守的规则，还可以举输入输出的例子 |

3. 在 Claude Code 里问"你有哪些 Agent Skill"，它能发现；再让它"总结以下会议内容"，它会判断归这个 Skill 管，询问是否使用，同意后读取 `SKILL.md`，按规则输出。

## 第一个核心机制：按需加载

流程里有三个角色：用户、Claude Code（工具）、大模型。

1. 用户提出请求。
2. Claude Code 把请求，连同**所有 Skill 的名称和描述**一起发给大模型（只有名称和描述，哪怕装了十几个 Skill 也只是一份轻量目录）。
3. 大模型判断该用哪个 Skill，告诉 Claude Code。
4. Claude Code 去读**这一个** Skill 的完整 `SKILL.md`。
5. Claude Code 把请求和完整 `SKILL.md` 再发给大模型，大模型按要求生成结果，返回给用户。

名称和描述始终可见，具体指令只有选中后才加载，省 Token。

## 高级用法一：Reference（参考资料）

- 问题：Skill 要做得更强（比如会议涉及花钱时自动提示财务合规），就得把财务规定、法律条文都塞进 `SKILL.md`，文件会变臃肿，开个简单早会也要加载一堆没用的内容。
- 做法：把长文件单独放（视频里是《集团财务手册.md》），在 `SKILL.md` 里写触发规则："仅在提到钱、预算、采购、费用时，读取这个文件，判断金额是否超标并指出审批人"。
- 特点：**条件触发**，不相关的会议里这个文件只躺在硬盘上，不占一个 Token 的上下文。
- 视频验证：会议里说订 1200 一晚的酒店 → 模型读了财务手册并给出提醒；与钱无关的会议 → 没读。

## 高级用法二：Script（脚本）

- 在 Skill 文件夹里放脚本（视频里是 `upload.py`，上传总结到服务器），在 `SKILL.md` 里写规则："用户提到上传、同步、发送到服务器时，必须运行 `upload.py`"。
- 特点：脚本是**被执行，不是被读取**。模型只关心怎么运行和运行结果，所以脚本写一万行，占用的上下文也几乎是零。
- 注意：如果没把运行方法写清楚，模型还是可能去读代码，这样就占上下文了，所以 `SKILL.md` 里要把怎么跑解释清楚。

| | 怎么加载 | 占用上下文 |
| --- | --- | --- |
| Reference | 被读取，内容放进上下文 | 会占用 |
| Script | 被执行，只看结果 | 几乎不占 |

## 渐进式披露：三层结构

| 层 | 内容 | 什么时候加载 |
| --- | --- | --- |
| 第一层 元数据层 | 所有 Skill 的名称和描述 | 始终加载（相当于目录） |
| 第二层 指令层 | `SKILL.md` 里除名称、描述之外的正文 | 模型判断问题和这个 Skill 匹配时才加载 |
| 第三层 资源层 | Reference 和 Script（官方规范里还有 Asset，视频认为和 Reference 定义有重叠，先忽略） | 只有用到时才加载（视频称"按需中的按需"，这是作者自己起的名字） |

## Skill 和 MCP 的区别

- Anthropic 官方文章的一句话："MCP connects Claude to data. Skills teach Claude what to do with that data."
  - MCP：给模型**提供数据**（昨天的销售记录、订单物流状态）。
  - Skill：教模型**怎么处理**这些数据（会议总结必须有议题，汇报文档必须有具体数据）。
- 为什么不全用 Skill（它也能写代码连数据）？能干不代表适合，就像瑞士军刀也能切菜，但没人这么干。
  - MCP 本质是一个**独立运行的程序**；Skill 本质是**一段说明文档**。
  - Skill 适合跑轻量脚本、处理简单逻辑；代码执行方面，Skill 的安全性和稳定性不如 MCP。
- 很多场景要**两者结合**。
